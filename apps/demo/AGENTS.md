## UI rules for the playground

- **Build with Base UI.** Use a `@base-ui/react` component whenever one exists for the element (button, tabs, toolbar, field, checkbox, tooltip, scroll area, accordion, and so on), and check its source or types before relying on a behavior. Use plain HTML only when Base UI has no equivalent, such as links and static text.
- **Check the size of new components first.** `Tooltip` is deliberately not used: it adds about 28 KB gzipped, so hover hints use the `title` attribute.
- **`Field.Root` wraps only its own label and control.** Any form control inside it, such as a checkbox, registers as the field's control and takes its label.
- **Style only with the Bezel variables.** Base UI ships no styles. All styling lives in `src/styles.css`, using `var(--...)` from `src/bezel/variables.css` or aliases mixed from them. Do not hard-code colors or fonts.
- **Every change must be responsive.** Write mobile-first CSS: base rules are for phones, and `min-width` queries add to them. The breakpoints are 700px (ASCII logo fits) and 1000px (panels sit side by side). Below 1000px, panels are tabs.
- **The page itself never scrolls.** Each panel scrolls inside itself, so new content goes in a pane, using `ScrollPanel` when it can overflow. Nothing may widen the page at any width.
- **Touch targets** are at least `--size-11` under `pointer: coarse`.
- **Panels stay mounted.** Anything that acts on a panel on another tab, like selecting text in the editor, must switch to that tab first.

## Bezel design tokens

- `design-tokens.json` at the repo root is the source for every design token. Edit it to change a color, size, font, or radius, or to add a CSS variable (add an `exportName` under `$extensions["new.bezel.app"]`).
- Files under the Bezel output folder (`variablesOutput`, `contextsOutput`, `fontsOutput` in `bezel.json`; `src/bezel/` by default) are generated. Never edit them; they are overwritten on every build.
- After changing `design-tokens.json` or `bezel.json`, run `npm run tokens` (or `npx bezel build`) and check the outputs were rewritten.
- Dark mode and other contexts are keys inside each token (`$root`, `dark`, `light`). Add a value under the context key instead of writing a CSS override.
- The Bezel app is the source of truth. `design-tokens-lock.json` records what was last synced or pushed; never edit it, and commit it together with `design-tokens.json`. `npx bezel diff` lists local edits that are not in Bezel yet.
- Sync through the Bezel MCP: write `get-design-tokens-file`'s `lockfileContent` to `.bezel/sync.json`, then run `npx bezel sync` (it writes both files and refuses to drop unpushed edits). To push (only when asked), run `npx bezel diff --json`, call `push-design-tokens` with its operations, then sync to update the lockfile. If it returns `needs-confirmation` (Bezel changed meanwhile), show the confirmation prompt word for word and call again with `confirmed: true` only after the user says yes.
- Never run `bezel init --force`; it discards the existing `bezel.json`. Use `--project` or `--tokens-version` to update a single key.
- Full guidance: the `bezel` skill in `.claude/skills/bezel/SKILL.md` or `.agents/skills/bezel/SKILL.md`.
